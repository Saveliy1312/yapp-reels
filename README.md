# yapp-reels

Автопубликация рилсов Yapp в Instagram (@we_yapp) по расписанию через официальный Instagram API,
а также постов в Threads (@we_yapp) через Threads API - см. раздел [Threads](#threads).

## Как это работает

- `queue.json` - очередь: время выхода (МСК), имя файла, подпись. Одна запись - один рилс.
- Ролики (`.mp4`) и обложки (`.png`) лежат в **Releases** этого репозитория. Workflow «Ролики и обложки на GitHub Pages»
  выкладывает на Pages файлы ещё не вышедших рилсов: Instagram забирает видео и обложку по публичной ссылке.
- Workflow «Публикация рилсов» запускается каждые полчаса. За 30 минут до слота он отдаёт ролик в Instagram,
  ждёт обработки и публикует ровно в назначенное время. Вышедшие рилсы отмечаются в `state/published.json`.
- Опоздал запуск GitHub - рилс выйдет сразу при следующем запуске (до 3 часов опоздания). Больше 3 часов - рилс
  помечается `missed`, workflow падает, и на почту владельца репозитория приходит письмо: такой рилс нужно выложить вручную.
- Перед публикацией скрипт проверяет последние посты профиля, поэтому один ролик дважды не выйдет.

Рилсы, выложенные через API, не видны в планировщике Meta Business Suite заранее - только после выхода.
А посты, запланированные в Meta Business Suite, не видны здесь. Перед тем как ставить новое (в очередь или в Meta),
сверяй оба календаря и выбирай свободное время, чтобы два поста не вышли одновременно.
Очередь по дням: **https://saveliy1312.github.io/yapp-reels/** (календарь со статусами и предпросмотром видео по клику на обложку, обновляется сам; переключатель «Все / Рилсы / Threads» показывает и расписание постов в Threads). Ход публикации - во вкладке **Actions**.

## Добавить новую партию

В очередь берём только ролики, чьи PR уже слиты в `main` репозитория fry-alt/yapp: исходник вышедшего ролика
должен лежать в `main`, а не в забытой ветке (правило в `video/CLAUDE.md` там).

1. Создать Release (тег, например `2026-10-14`) и загрузить в него `ИМЯ.mp4` и `ИМЯ.png` для каждого ролика.
2. Дописать записи в `queue.json` (`media` = `ИМЯ` без расширения) и закоммитить - Pages обновятся сами
   (если файлы загружены в Release позже коммита - Actions → «Ролики и обложки на GitHub Pages» → Run workflow).
3. Actions → «Публикация рилсов» → Run workflow → `check`: проверит токен и что все файлы доступны;
   `probe`: Instagram пробно примет и обработает ближайший ролик, но публиковать не будет.

Правила расписания сериалов - в [docs/КАК-ВЫКЛАДЫВАТЬ-СЕРИАЛЫ.md](docs/КАК-ВЫКЛАДЫВАТЬ-СЕРИАЛЫ.md): одна серия в день в одно время, между сериями
минимум 2 обычных ролика, соседние обычные ролики - разных рубрик и цветов обложки.

## Статистика

Workflow «Статистика Instagram» каждый день в 05:50 МСК сохраняет метрики последних 50 постов: просмотры, охват,
сохранения, репосты, средний досмотр рилса и во сколько раз пост обошёл медиану своего типа.
Читать - [state/insights.md](state/insights.md), данные для скриптов и Claude - `state/insights.json`
(там же история числа подписчиков). Запустить вне расписания: Actions → «Статистика Instagram» → Run workflow.

## Threads

Посты в Threads идут из `threads.json` так же, как рилсы: workflow «Публикация в Threads» запускается каждые полчаса
и выкладывает пост точно в назначенное время (опоздание до 3 часов - выйдет сразу, больше - `missed` и письмо на почту).
Вышедшие отмечаются в `state/threads.json`, перед публикацией скрипт сверяет последние посты профиля, чтобы не было дублей.

Запись в очереди:

```json
{
  "id": "2026-10-13-1200",
  "at": "2026-10-13T12:00:00+03:00",
  "text": "Текст поста, до 500 знаков",
  "topic": "Английский язык",
  "poll": ["Вариант 1", "Вариант 2"],
  "images": ["slang-01.png"],
  "replies": ["Продолжение треда", "Ещё продолжение"]
}
```

Обязательны `id`, `at`, `text`. По желанию: `topic` - тема поста (одна), `poll` - опрос на 2-4 варианта
(только без картинок), `images` - 1 картинка или карусель до 20 (файлы с расширением кладутся в Release, как ролики),
`replies` - продолжение: каждый следующий пост выходит ответом на предыдущий. Проверить очередь:
Actions → «Публикация в Threads» → Run workflow → `check`.

### Подключение (один раз)

1. Профиль Threads для we_yapp: войти в приложение Threads через Instagram we_yapp, профиль публичный.
2. developers.facebook.com → приложение → **Add use case** → «Access the Threads API» (если Meta не даёт добавить
   его к «Yapp Reels», создать отдельное приложение с этим use case). Права: `threads_basic`,
   `threads_content_publish`, `threads_manage_replies` (для продолжений треда), `threads_manage_insights` (на будущее).
3. App roles → Roles → **Threads Testers** → добавить we_yapp. Принять приглашение в Threads:
   Настройки → Аккаунт → Разрешения для сайтов → Приглашения.
4. Выпустить токен для we_yapp (генератор токенов в настройках Threads use case или Graph API Explorer с `threads.net`).
   Если токен короткий (живёт час), обменять его на 60-дневный локально:
   `TH_TOKEN=короткий TH_APP_SECRET=секрет_приложения node scripts/threads.mjs exchange` → токен в `.new-token`.
5. Положить токен в секрет: `gh secret set TH_TOKEN -R Saveliy1312/yapp-reels` и вставить токен.
   Продлевает его тот же workflow, что и токен Instagram (нужен `GH_PAT`).
6. Actions → «Публикация в Threads» → Run workflow → `check`: должен показать `аккаунт we_yapp`.

Пока секрета `TH_TOKEN` нет, workflow ничего не делает и не падает.

## Секреты (Settings → Secrets and variables → Actions)

- `IG_TOKEN` - токен Instagram API with Instagram Login для we_yapp с правами `instagram_business_basic`,
  `instagram_business_content_publish` и `instagram_business_manage_insights` (для статистики). Живёт 60 дней.
- `GH_PAT` (по желанию) - fine-grained токен GitHub только на этот репозиторий с правом **Secrets: Read and write**.
  С ним workflow «Продление токена Instagram» каждый понедельник сам продлевает `IG_TOKEN`. Без него токен нужно
  перевыпускать вручную раз в 60 дней.
- `TH_TOKEN` - токен Threads API для we_yapp (см. раздел [Threads](#threads)). Живёт 60 дней, продлевается вместе с `IG_TOKEN`.

## Чего API не умеет

Закрепить рилс в профиле, добавить в подборку (Reels-серию) и выложить сторис - это делается вручную в приложении.
